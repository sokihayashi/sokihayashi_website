# v2 の方針(2026-11-16)

ローカルの Claude Code / Codex / Gemini CLI などに作業を渡すときの引き継ぎ資料。

## 目的

- 作品をジャンルのタグで整理し、一つずつ説明を付ける
- サイト全体をインタラクティブにする。驚きの要素を重視する
- 費用はなるべく抑える

目標水準の参考:
tbwahakuhodo.co.jp / feau.jp / goodpatch.com/15th / aratanagara.com / panzoo.net /
yejji.net / penguin-capital.co.jp / anri.vc / funtech.inc
(9サイト中7つが three.js、5つが Lenis。土台は Astro が4、Next.js が3。ノーコードは0。)

## コンセプト

**価値は最初からある。形だけがない。掬って、器に流し込むと、形になる。**
(本人の一文「価値は、はじめ液体のように形がない。それを掬い、象り、あらゆる接点へ流し込む。」から)

- 液体は1種類。水滴(HYDRA)と同じ、黒い艶に白い流紋と色のにじみ
- 器 = 案件。1器=1案件。空のときは3辺の線だけ(上は開いている)
- 水滴を切ると、飛沫が器の口へ飛ぶ。器に液が上がり、満ちると澄んで作品が見え、線は外れる
- 液体は分かれてもよいし、増えてもよい。飛び散りは演出として使う。ただし飛沫には必ず行き先がある
- 文字は少なく。名前、核の一文、作品名。言葉を足して埋めない
- 基本の作りは参考サイトに倣い、差は液体の表現で付ける
- 文字は常に水平。動くのは位置だけ

経緯: 「切る」を全体の文法にした版 → 飛沫と液体カーソルを足した版(本人評「ガチャガチャしてコンセプトに一貫性がない」)→ 器の版。
6つの専門の目線で合議した記録は `docs/council/` にある。決定は下の「合議で決めたこと」。

## 合議で決めたこと(2026-11-16)

採用:
- 無題で押せない画像の壁をやめ、1器=1案件にした(142枚 → 27案件。残り16枚は未分類)
- 器の比率は作品のまま。裁たない
- 器に入る液を水滴と同じ素材にした(写真を波形に切り抜く方式をやめた)
- トップの絞り込みをやめ、/works だけに置いた。状態は URL に残す。0件のタグは押せない
- 現在地を URL に残す(`#w=3`)。戻る・共有・再訪では演出を飛ばす
- スマホは真縦、ブラウザ本来のスクロール、1画面1案件
- 画像はリポジトリ内に置いた(Wix の直接参照をやめた)
- 水滴が画面の外にあるあいだは描画を止める。動きは経過時間で計算する
- 時計は非表示にした(記述は残してある)
- 最後に空の器をひとつ置き、Contact へつなぐ

不採用(本人の判断が先にあるもの):
- 「飛沫を削る」「切るをやめる」→ 飛び散りは演出として残す
- 「液量の保存(水滴が痩せる)」→ 液体は増えてよい
- 実績名の列挙、肩書き、各作品の説明文の追加 → 言葉は増やさない

保留:
- 器を実物の輪郭にする(瓶・Tシャツ・駒など)
- HYDRA を埋め込み枠から出し、素の WebGL で本体の描画面1枚に移す(p5.js 4.2MB をやめる。見積もり2〜3日)
- 白地の画像を小さく扱う
- 書体(いまは仮に Shippori Mincho と Zen Kaku Gothic New)

## タグ(2軸)

- 領域 `domain`:Branding / Graphic / Photography / Movie / 3D / UIUX・Web / 立体
- 立場 `stance`:Client work / Original work

## 作品1件あたりの項目

- 短文 `summary`(60〜80字):何を、誰のために作ったか
- 長文(本文、300〜400字):課題、判断、やったこと、結果
- 年、クライアント、担当範囲、画像、トップ掲載フラグ、並び順

## 技術

| 役割 | 使うもの | 費用 |
|---|---|---|
| 土台 | Astro | 0円 |
| コード置き場 | GitHub(このリポジトリの `v2/`) | 0円 |
| 公開サーバー | Cloudflare Pages 無料プラン(アカウント作成済み) | 0円 |
| 作品データ | このリポジトリの Markdown。管理画面が要るなら microCMS Hobby | 0円 |
| ドメイン | soki-hayashi.com を継続 | 更新料のみ |

- Vercel の無料プランは非商用限定のため使わない
- Wix は切り替え完了まで維持し、その後に解約する
- 目標の構造は3つ:全画面に常駐する1枚の描画面、自前で握るスクロール、再読み込みしないページ遷移
  - スクロールは実装済み(`v2/src/scripts/stage.ts`。PCは自前、スマホはブラウザ本来のもの)
  - ページ遷移は Astro の View Transitions でつないである(演出は未着手)
  - 描画面は HYDRA を埋め込み枠のまま使っている。常駐化は次の段階
- 器と「注ぐ」動きは `v2/src/components/Vessel.astro`、`v2/src/scripts/pour.ts`、`v2/src/styles/global.css` の「器」
- 画像は `v2/public/img/wall/NNN.webp`(長辺1500px)と `NNN-s.webp`(560px)。番号と案件の対応は各 .md の `images`

## 注意

- **`main` は Wix のサイトと同期している。** `src/`(Velo のコード)を変えて main に入れると、Wix 側に反映される。v2 の作業はブランチで行い、`src/` には触れない。
- デザインは勝手に変えない。懸念を伝え、判断は Soki に委ねる
- 本番公開(ドメイン切り替え、Wix の変更)は、明示的な OK が出たものだけ
